先付后餐与先餐后付双模式支付体系设计
餐饮业态多样，早餐店、面馆、快餐店通常采用先付款后用餐模式避免跑单风险；部分正餐、火锅店支持先用餐后付款提升用餐体验。系统标准版支持先付款后用餐，高级版同时支持两种模式满足不同餐饮商家经营需求。两种模式在订单状态流转、支付时机和风险控制上存在显著差异。

先付后餐模式下用户选好菜品后立即进入支付环节。支付成功后订单状态变更为“已支付/待接单”，系统触发订单打印厨房开始制作。若支付失败或用户取消支付，订单状态保持“待支付”，超时后自动取消。该模式核心优势是零跑单风险，适合快餐、小吃等即买即走场景。技术实现上支付回调是关键环节：后端需验证微信支付回调签名确认支付成功后更新订单状态并触发后续动作。

先餐后付模式下用户下单后无需立即支付，订单直接进入“待接单”状态厨房开始制作。用户用餐结束后通过小程序主动发起支付，或由店员在商家中心发起收款。该模式提升用餐体验但存在跑单风险。系统通过以下措施控制风险：记录用户手机号和微信openid便于后续追款；对未支付订单进行标记，店员可查看未支付订单列表；支持店员端手动发起收款提醒。先餐后付模式通常与钱包储值功能结合，用户可预存金额用餐后自动扣款彻底消除跑单风险。

双模式下的订单状态机需要兼容两种流程。核心状态：待支付、待接单、制作中、待取餐、已完成、已取消。先付模式下订单从“待支付”经支付成功后进入“待接单”；先餐后付模式下订单直接进入“待接单”，支付动作发生在用餐后。系统通过order_type字段区分支付模式，状态流转逻辑根据order_type动态调整。

系统支持微信支付和钱包余额支付两种方式。微信支付通过微信支付统一下单接口实现，支付成功后回调通知后端。钱包余额支付直接从用户钱包扣除金额，需保证余额充足并记录流水。系统支持混合支付：用户可先使用钱包余额，不足部分再通过微信支付补足。支付流水表记录每笔支付金额、方式、时间、关联订单便于财务对账。

先餐后付模式下系统需防范恶意逃单。措施包括：限制未支付订单数量，用户有未支付订单时不可再次下单；记录用户信用数据，多次逃单用户加入黑名单；店员端提供未支付订单提醒功能。支付异常处理方面系统记录支付日志，对支付失败、回调超时等情况进行重试和人工干预。先付后餐和先餐后付双模式支付体系需要灵活订单状态机和严谨支付流程设计，合理风险控制措施和异常处理机制是保障商家资金安全和用户用餐体验的技术基础。
